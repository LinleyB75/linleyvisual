Frequently Asked Questions

Can I inspect the raw code behind these portfolio examples?

Yes. My email code is on GitHub, and the View Code buttons link to the repository. You can read the raw HTML, CSS, MJML and templating logic and judge the code quality yourself.

Which frameworks and technologies are used across these templates?

The portfolio includes builds in semantic HTML/CSS and MJML, plus a transactional receipt built as a Brevo template. I also work with Handlebars and Liquid templating.

How do these templates handle legacy Outlook and Dark Mode rendering?

Layouts that need it use ghost tables and VML for classic Outlook desktop clients, and explicit colour-scheme settings for dark mode. My blog notes show specific fixes, including which clients I retested them in.

What deliverables do I receive when a custom design build is complete?

On a custom build I deliver clean, minified HTML and an organised folder of compressed assets. I can also set the template up in your email platform and run live test sends.

Are these email templates tested across real mobile and desktop clients?

Yes. I test emails across major email clients and devices, including Gmail, Apple Mail, Outlook desktop and web, iOS and Android, and fix what breaks before delivery. Clients render email differently, so the result matches the design as closely as each client allows.

Can these templates be integrated into major Email Service Providers (ESPs)?

Yes. I set templates up in Mailchimp, Brevo, Klaviyo, MailerLite and Kit, using each platform's own tags for names and dynamic content.

How are multi-column layouts handled on smaller mobile screens?

Multi-column layouts and image-text blocks use responsive breakpoints and MJML stacking, so they drop into a clean single column on mobile.
