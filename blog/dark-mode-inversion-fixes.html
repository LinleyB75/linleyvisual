What dark mode inversion did to my newsletter, and the fixes

Published 4 October 2026

dark-modeoutlook-commacosbuttonsfootermjml

The newsletter

This is a Re-cafe coffee newsletter built in MJML on a near-black background, with red brand text and a white call-to-action button. After the dark mode fixes it rendered well in 130 clients. Three problems came up along the way, all caused by clients inverting or recolouring parts of the design. This post covers each one.

1. The button's colours (Outlook.com and Outlook)

Problem: the button is meant to be white with red text and a grey border. In Outlook.com's dark mode the client recoloured it. In one Outlook client, which I believe was Outlook 2024 (120 DPI), the button text turned blue after inversion.

Fix: Confirmed.

Rules that were needed: the Outlook.com attribute rules, and the text fill colour with a span wrapper on the link text.

Rules that weren't needed in my testing: a prefers-color-scheme: dark block, and a bgcolor and gradient background.

Outlook.com's dark mode marks the colours it rewrites with attributes: data-ogsc for text and data-ogsb for backgrounds. CSS can target them. The button is a small hand-built table inside an mj-text block, so every colour is under my control:

<table role="presentation" class="cta-btn" border="0" cellpadding="0" cellspacing="0" align="center" style="margin: 0 auto; border-collapse: separate;">
  <tr>
    <td class="cta-btn-cell" align="center" valign="middle" bgcolor="#ffffff" style="width: 240px; padding: 20px 33px; background-color: #ffffff; border: 4px solid #898989; border-radius: 25px;">
      <a class="cta-btn-link" href="https://example.com/" target="_blank" style="display: inline-block; font-family: Arial, sans-serif; font-size: 22px; line-height: 22px; font-weight: normal; text-decoration: none; white-space: nowrap; color: #FF0000;">
        <span style="color: #FF0000; -webkit-text-fill-color: #FF0000;">Learn More</span>
      </a>
    </td>
  </tr>
</table>

The email has global resets that remove table and cell borders, which would have stripped the button's border and rounded corners, so the button is exempted:

/* global resets in the email */
table { mso-table-lspace: 0pt !important; mso-table-rspace: 0pt !important; border-collapse: collapse !important; border: 0 !important; }
td { border: 0 !important; mso-line-height-rule: exactly !important; }

/* the button is exempted from them */
table.cta-btn { border-collapse: separate !important; }
td.cta-btn-cell { border: 4px solid #898989 !important; }

The colour locks that did the work:

a.cta-btn-link, a.cta-btn-link:visited, a.cta-btn-link:hover, a.cta-btn-link:active, a.cta-btn-link span {
  color: #FF0000 !important;
  -webkit-text-fill-color: #FF0000 !important;
  text-decoration: none !important;
}

/* Outlook.com dark mode: background and text attributes */
[data-ogsb] td.cta-btn-cell { background-color: #ffffff !important; }
[data-ogsc] a.cta-btn-link, [data-ogsc] a.cta-btn-link span { color: #FF0000 !important; }

The Outlook 2024 (120 DPI) blue text was fixed by these same button rules. I didn't separate out which one fixed that client specifically.

2. The footer colour and the social icons

Problem: colour inversion in dark mode changed the footer's original design too much, and the brand colour in particular would have been compromised. The social media icons were also affected by the inversion.

Fix: I changed the footer background colour, and changed the social icons. The footer and social sections now use a dark grey, #3D3D3D, and the icon elements use the same grey for both background and colour:

<mj-section background-color="#3D3D3D" padding-top="8px">
  <mj-column background-color="#3D3D3D">
    <mj-text align="center" color="#FFF">Follow us on:</mj-text>
    <mj-social font-size="16px" icon-size="34px" mode="horizontal" align="center" color="#fff">
      <mj-social-element name="facebook" href="https://www.facebook.com/" background-color="#3D3D3D" color="#3D3D3D"></mj-social-element>
      <mj-social-element name="instagram" href="https://www.instagram.com/" background-color="#3D3D3D" color="#3D3D3D"></mj-social-element>
      <mj-social-element name="twitter" href="https://twitter.com/" background-color="#3D3D3D" color="#3D3D3D"></mj-social-element>
      <mj-social-element name="linkedin" href="https://www.linkedin.com/" background-color="#3D3D3D" color="#3D3D3D"></mj-social-element>
    </mj-social>
  </mj-column>
</mj-section>

The footer was a different colour before, though I didn't record which one. I also didn't record which clients inverted the footer and icons, so I won't name any. The fix held across the 130 clients I tested.

3. Footer text black instead of white (macOS dark mode)

Problem: in dark mode in macOS Tahoe (dark) and macOS Golden Gate (dark3) (beta), the footer text rendered black instead of white on the grey background.

Fix: Confirmed in both macOS clients.

What I changed: Apple data detector handling, and explicit backgrounds on the footer blocks. I used both together and didn't test them separately.

Apple's mail apps can turn text they recognise, such as a street address, into a link and restyle it. The footer has an address, so I switched the detectors off with four meta tags and added a rule that makes any detected link inherit its colour from the text around it. I didn't confirm this as the exact cause, so treat it as my best explanation:

<meta name="format-detection" content="telephone=no">
<meta name="format-detection" content="date=no">
<meta name="format-detection" content="address=no">
<meta name="format-detection" content="email=no">
a[x-apple-data-detectors] {
  color: inherit !important;
  text-decoration: none !important;
  font-size: inherit !important;
  font-family: inherit !important;
  font-weight: inherit !important;
  line-height: inherit !important;
}

I also set the background colour explicitly on every footer block, so no client has to guess it. The viewing options block, for example, sets the same grey on the section, the column, and the text container:

<mj-section background-color="#898989" padding="10px 0px 18px 0px">
  <mj-column width="100%" background-color="#898989">
    <mj-text container-background-color="#898989" ...>

The social and footer sections do the same with #3D3D3D, as in the code above.

What I retested

  • Outlook.com dark mode and the Outlook client with the blue button text: fixed.
  • macOS Tahoe (dark) and macOS Golden Gate (dark3) (beta): footer text white on grey.
  • Overall: the newsletter rendered well in 130 clients.

I haven't listed all 130 here, so test your own audience's clients before relying on any of this.

Takeaway

Dark mode is not one behaviour. The same email gets recoloured differently in each client, and the button, footer, and icons are the first places to look. Test them in many clients, and lock the colours that carry your brand.
